---
name: use-onboarding
description: Help a person explore a newly opened Design Studio and start their first prototype. Use when Onboarding is enabled; installation and configuration use their own procedures.
---

Read the module [README](../../README.md) and the repository instructions. Confirm which studio folder the person is working in. A browser preview alone does not establish the agent's workspace.

1. Explain the first-use introduction if it is open. If it has been dismissed, use the Manual or walk them through the studio directly. Offer an available sample prototype and explain what they can try.
2. Explain that systems supply components, styles, and product guidance. Use the actual registered systems rather than assuming the starter examples remain. Label the bundled Product and Marketing systems and Feedback Inbox and Design Studio Marketing prototypes as example content when they are still present. Explain that they should be customized, replaced, or removed to fit the person's own needs; keep Studio as the application system.
3. Ask what they want to explore. Help them describe the problem, audience, and what they want to learn. Offer a brief, diagram, lo-fi wireframe, hi-fi clickable prototype, or canvas only when its module is enabled; start with what helps answer their question. Follow the current Build Prototype skill, contributor registration, and assigned system guidance when they want to create work.
4. When they want to share, distinguish published viewing links, local preview links, and source-repository access. Use the platform publishing guidance for hosting and the contributor procedures for joining and permissions. Offer modules only when they need an additional capability.
5. Keep instructions in ordinary design language. Let them explore or skip the introduction. Do not install tools, change shared configuration, delete samples, or replace a system merely to complete onboarding.

When the person wants their own toolkit, follow [Setup Design System](../../../systems/skills/setup-design-system/SKILL.md). Start with their intended prototype or assess their existing React components and theme. Systems also own fonts, icons, logos, and shared images. Keep this an available next step rather than a prerequisite for exploring. Do not require product context or a skills collection to finish the welcome flow.

If they need installation, use the setup entry point. If they want to personalize the running studio, use Configure Studio. Opening Welcome is not evidence of completed setup or a first prototype.
